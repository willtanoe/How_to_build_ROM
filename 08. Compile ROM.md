# 08. Compile ROM

## Setup Environment

Move to your ROM source folder and source the build environment:

```bash
cd ~/super
. build/envsetup.sh
```

## Lunch Your Device

```bash
lunch superior_ginkgo-userdebug
```

Format: `lunch <romname>_<codename>-<variant>`

Build variants:
- `userdebug` -- like user build but with root access and debug capability. Recommended for testing.
- `user` -- production build, no root, minimal debug. Use this for releases.
- `eng` -- engineering build, full debug, slowest.

## Compile

### Using `make`:

```bash
make bacon -j$(nproc --all) | tee ~/super/build.log-$(date '+%Y%m%d-%H').txt
```

### Using `mka` (recommended):

```bash
mka bacon -j$(nproc --all) | tee ~/super/build.log-$(date '+%Y%m%d-%H').txt
```

**Difference between `make` and `mka`:**
- `make` is the standard GNU make tool
- `mka` is a wrapper around `make` provided by AOSP that handles some Android-specific build logic and is generally more reliable for ROM building

**About `-j` flag:**
- Controls how many parallel jobs run simultaneously
- Rule of thumb: use 2x your CPU thread count, e.g. 8 cores / 16 threads = `-j16`
- Or just use `-j$(nproc --all)` to auto-detect and use all available threads

## Output

If the build succeeds, your ROM zip will be in:

```
out/target/product/<codename>/
```

Look for a file named something like:

```
SuperiorOS-<version>-<date>-<codename>-OFFICIAL.zip
```

## Checking Build Result

A successful build ends with a message similar to:

```
#### build completed successfully (01:23:45 (hh:mm:ss)) ####
```

If you see errors, check your build log:

```bash
grep -i "error:" ~/super/build.log-*.txt | tail -50
```

Then head to the `z. Fix error.md` file or submit an issue.
